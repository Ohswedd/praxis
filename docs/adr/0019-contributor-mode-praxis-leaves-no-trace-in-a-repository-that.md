# 19. Contributor mode: praxis leaves no trace in a repository that is not ours

- Status: accepted
- Date: 2026-07-28

## Context
praxis writes real files into a project: CLAUDE.md, .claude/settings.json, .praxis.toml, a /docs tree, CHANGELOG.md, ADRs, and an edit to .gitignore. In your own repository that is the point. In a repository you only contribute to, every one of them is a file the maintainers never asked for, sitting one git add -A away from a pull request that should have contained a bug fix. Making bootstrap automatic (ADR-0018) turned that from an occasional embarrassment into a guarantee, so the two changes could not ship separately.

## Decision
praxis resolves a workspace mode (owner or contributor) before writing anything, through the same ladder as every other setting: PRAXIS_MODE, then .claude/.praxis/workspace, then .praxis.toml [workspace] mode, then detection. Detection is offline and asks one question, whether the address configured to commit here has ever committed here: a repo with a remote, real history, and no commit from your git email is somebody else's project. Every uncertain case resolves to owner, because a wrong contributor verdict silently withholds setup a user expected in their own project, while a wrong owner verdict is what we are trying to prevent, so the asymmetry is paid where it is cheap and the verdict is printed with its reason every session. In contributor mode the brief is CLAUDE.local.md and the settings are .claude/settings.local.json, the two locations Claude Code documents for local uncommitted configuration; praxis config layers a git-excluded .claude/.praxis/praxis.toml over the committed one; and /docs, CHANGELOG.md, docs/adr/ and docs/design/ are joined only if the project already has them, otherwise kept under .claude/.praxis/knowledge/. Containment is three layers: a marked block in GIT_DIR/info/exclude, the file gitignore(5) reserves for per-clone patterns that are never shared; a PreToolUse guard that refuses to stage a praxis artifact in either mode, refuses to write a praxis path into a .gitignore that is not ours, and verifies rather than assumes on a stage-everything command; and the directives that state the artifact map every session.

## Consequences
A contributor clone ends a session byte-for-byte as it started, apart from the change the user asked for, and the guarantee is mechanical rather than remembered: excluded files are invisible to git status, unreachable by git add -A, and absent from praxis's own change detection, so they also cannot make the Stop gate see a dirty tree. The exclusion alone proved insufficient (git add --force overrides it by design, and a command string can always be written another way), so the guarantee is completed by an index check before commit/push/stash: see ADR-0021. The join-what-exists rule means a project's changelog is still updated by a contribution, which is what its maintainers expect. Costs: detection can misread a fresh fork or a machine whose git email differs from the one in the history, which one toggle fixes; the exclude write is a side effect in a SessionStart hook, fails open, and is re-checked by the guard before any broad staging; and every artifact path now resolves through common rather than being hard-coded, which is one indirection more but one place to change.

## Alternatives considered
A per-repo opt-in toggle with no detection was rejected: a forgotten toggle is exactly the failure being prevented, and the user would only discover it in the pull request. Storing local artifacts outside the repo (in ~/.praxis/<hash>/) was rejected as unusable: the files are read and edited constantly, and .git/info/exclude already gives a complete guarantee in place. Blocking every .gitignore edit in contributor mode was rejected as over-broad: only an edit carrying a praxis path is refused, so an ordinary ignore rule a contributor legitimately needs still goes through.
